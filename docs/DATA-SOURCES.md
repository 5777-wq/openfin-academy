**为什么用官方源做 VIX 和美债**：东财对应 secid 的 K 线是空的，而这两个序列是本站"危机复盘"的支柱（VIX 衡量恐慌、美债收益率衡量信用定价），不能凑合。

**财政部 CSV 的坑**：表头带引号（`Date,"1 Mo","3 Mo",...`），解析时必须剥掉引号再找列，否则整列找不到。

**CBOE CSV 的坑**：末尾有脏行（月份为 31 之类的非法日期），必须校验月 1–12、日 1–31 再收。

## 三、危机回放包

`data/history/crisis-*.json` 由采集脚本组合而成，**日频**：

| 包 | 区间 | 交易日 | 序列 |
|---|---|---|---|
| `crisis-1987` | 1987-06 → 1988-12 | 415 | 标普500、NYMEX原油 |
| `crisis-1990` | 1987-04 → 1993-06 | 1629 | 日经225、标普500、恒生、黄金、原油、美债10Y |
| `crisis-1994` | 1993-10 → 1995-12 | 586 | 标普500、美债10Y、黄金、原油、恒生 |
| `crisis-1998` | 1997-04 → 1999-06 | 586 | 恒生、日经225、标普500、黄金、美债10Y、VIX |
| `crisis-2008` | 2006-01 → 2010-06 | 1145 | 标普500、黄金、原油、美债10Y、VIX |

```json
{
  "id": "2008",
  "title": "2008 年次贷危机",
  "from": "2006-01-01", "to": "2010-06-30", "freq": "D",
  "dates": ["2006-01-03", "..."],           // 规范日期轴
  "series": [{ "key": "SPX", "name": "标普500", "points": [{"t":"...","v":123}] }],
  "events": [{ "t": "2008-09-15", "title": "雷曼兄弟破产", "note": "..." }],
  "source": "东方财富（指数/商品）· CBOE（VIX）· 美国财政部（美债收益率）"
}
```

**为什么必须是日频**：月频会把崩盘日藏起来。1997 年 10 月恒指月末收 16459，但当月最低收盘只有 9059——只看月末价，这场危机根本看不见。日频才能让读者拖到那一天。

**1987 那场只有 2 条序列**，因为 VIX 是 1990 年才有的、美债收益率官方序列也从 1990 年开始。这是真实的数据边界，页面上直接写明。

## 四、数字对账工具

写文章时用它查准确值，别凭印象写数字：

```bash
node scripts/reconcile.mjs 2008-09-15 SPX GC00Y VIX   # 查某天的收盘价（优先日频）
node scripts/reconcile.mjs --crisis 1990               # 查某场的峰谷、跌幅、最惨一天
node scripts/reconcile.mjs --list                       # 列出所有序列
```

`_test/run-all.mjs` 里还有 20 多条断言，把文章里引用的关键数字与 `data/history` 锁死——**改了数据，测试会红。**

## 六、序列注册表

`data/series-map.json` 是**唯一事实源**：每条序列的 id、名称、单位、频率、来源、起止日期、点数。

**正文只能引用注册表里的 id。** 杜绝"临时抓一个数就写进文章"——那种数字读者无法核对，也无法随采集更新。

## 七、已知不可用

| 源 | 状态 | 原因 / 替代 |
|---|---|---|
| FRED `fred.stlouisfed.org` | 本机网络不可达 | 已由财政部 CSV + CBOE CSV 完全替代 |
| Stooq | 403 Access denied | 已由东财 `push2his` 覆盖同类需求 |
| 东方财富 `171.*` 的历史 K 线 | 返回空数组 | 用财政部官方 CSV |
| 东方财富 `push2his`（K 线） | 某些网络下 socket 被掐 | 采集器已加**腾讯 `ifzq` 备源**（只覆盖 A 股指数）：东财取不到时自动改用腾讯，`source` 字段照实记下用的是哪个源 |
| 个股月线的**拆股复权** | 腾讯给的是不复权价 | 英伟达 2024-06 十拆一，在月线里就是一道 10 倍断崖（1096 → 123），不修的话「峰谷跌幅 -99%」全是假的。修法：**日期取腾讯**（当月最后一个交易日），**价取 Yahoo Finance**（已按拆股复权）；拆股事件的**比例**取自 Yahoo，**生效位置**由价格断崖自己定位（只看比值会把真实暴跌误判成拆股）。`_test/run-all.mjs` 有一条断言专门盯这件事：价格类序列不许出现单月跌超 70% 的假断崖 |
| 个股历史里的**分红** | 未复权 | 站内个股序列是**价格涨幅**，不是总回报。页面上照实写了"不含分红" |
| 白银 2011 年前的数据 | 缺失 | 标注目录起点，不外推 |

## 八、降级链

```
主源成功 → 正常显示，标数据源名
主源失败 → localStorage 缓存 + "降级"角标 + 缓存时间
缓存也没有 → 显示 "--"，绝不白屏
```

**内容页不等行情。** 行情源慢或不可达时，内容照常渲染，报价条显示"行情加载中"或"暂不可用"。

## 九、更新

GitHub Actions 每天跑一次 `collect-history.mjs` + `build-content.mjs`，有变化就提交。也可以本地跑：

```bash
node _scripts/collect-history.mjs                  # 全量
node _scripts/collect-history.mjs --only=treasury  # 只跑某一环
```

`--only` 可选值：`east`、`vix`、`treasury`、`crisis`、`chain`。
