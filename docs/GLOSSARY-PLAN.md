# 术语库规划（研报数据 · 基金策略 · 宏观微观 · 机构 · 期权）

> 目标：读者在终端里遇到任何一个词，都能点开看到「这是什么、怎么算、怎么用、坑在哪」，
> 而不是只得到一个定义。分类要按**读研报/看盘时真正会遇到的顺序**排，不是教科书目录。

**当前状态：213 个词条，十个分类全部有内容。** 下表的「现状」是真实分布，不是计划。

## 一、为什么要分类

原来 39 条术语是一锅粥：有的是资产（黄金、原油），有的是指标（PE、换手率），有的是机构（桥水、LTCM），
有的是策略（动量选股、因子 ETF）。读者不知道从哪看起，也不知道"这词属于哪一类"。

**十个分类**（`cat` 字段，术语库 + 术语页 + 速查页都用它）：

| cat | 分类 | 覆盖什么 | 现状 |
|---|---|---|---|
| `data` | 研报数据 | 研报/行情软件里天天出现、但没人解释的数 | 24 |
| `fund` | 基金与策略 | 基金产品与投资策略的门类 | 32 |
| `asset` | 资产类别 | 钱能投在哪 | 36 |
| `option` | 期权与期权策略 | 期权是什么、怎么定价、经典组合怎么搭 | 20 |
| `macro` | 宏观经济 | 整个经济的账 | 16 |
| `basic` | 基础概念 | 绕不开的概念：利率与定价、公司与商业模式、历史上的大泡沫 | 16 |
| `micro` | 微观与行为 | 公司层面，与人的偏误 | 10 |
| `player` | 机构与人物 | 谁在市场上 | 11 |
| `risk` | 风险与交易 | 怎么算风险、怎么下注 | 12 |
| `tech` | 技术指标 | 图表上那几条线 | 12 |

**为什么单开一个 `option` 分类**：期权有它自己的一整套语言（行权价、价内价外、Greeks、波动率微笑），
还有一整套组合（备兑、保护性看跌、跨式、价差、铁鹰）。塞进 `asset` 会变成一堆同义反复的资产类别，
塞进 `fund` 它又不是基金，20 条挤在一类里读者翻不动。单开一类之后，
它内部还能再按「基础 → 定价 → 策略」排出顺序。

## 二、页面结构

- `#/terms` 术语库索引 —— **按分类分组**，每组带计数 + 「入门三词」导览 + 该分类的速查表入口
- `#/term/<id>` 词条页 —— 四段式（一句话 / 比喻 / 数字 / 坑）+「去看历史数据」「回到 OpenFinLens」
- `#/data` **速查表**（`#/data?cat=xxx`）—— 十个分类各一张表：每行「是什么 · 什么时候会骗人」，
  读者不懂某个数时从这一页进，比在 180 多条术语里翻要快
- 每条术语带 `sym`（终端里的 symbol）→ 词条页直接能跳该标的的行情

### 组内按「读者遇到的顺序」排，不是字母序

以前速查表里是按 id 字母序排的——读者看到「ETF、ETF 费率、ETF 折溢价、事件驱动……」，
像字典，不像一份读物。现在按信号分层（`js/views/term.js` 的 `orderTerms`）：

0. 站内有**专文**的（links 指向内容页）——读者最可能从它开始读
1. 行情终端会链到它的（`vendor/core/academy-gloss.js` 的映射表）——在行情里能撞见
2. 终端悬停时会解释的概念词（`vendor/core/explain.js` 的 `CONCEPT_NOTES`）
3. 有 `sym` 的（能直接看行情）——有真实数据可以对账
4. 其余按 id 升序（结果确定，不随运行环境变）

注意 0 和 1/2 必须分开：`links` 里既有指向专文的，也有只是「相关词条」的，
混在一起当信号，排序会被交叉引用冲淡。

### 「名称由来」是词条卡的一段

读者看到「日经225」「标普500」「道琼斯工业指数」，第一反应是「225 是几家？500 是几家？」
——这个答案比历史点位更重要，所以词条卡在「一句话」之后多了一段「名称由来」，
用 `name` 字段承载。已覆盖的指数见下面「指数名字里的数字」。

### 「入门三词」不重复下面的一句话

速查表页的入门三词卡片显示的是**比喻**，不是「一句话」——下面那张表的第二列已经是一句话了，
再抄一遍就是重复；比喻是新的信息。术语库索引页同理。

## 三、数据模型

```jsonc
{
  "id": "pe-ratio",
  "term": "市盈率",
  "alias": "PE / P/E",
  "cat": "data",              // 十个分类之一
  "one": "…",                  // 一句话
  "name": "…",                 // 名称由来（可选）：名字里的数字是什么意思
  "metaphor": "…",            // 比喻
  "number": "…",               // 一个真实数字
  "pit": "…",                  // 坑
  "sym": "sh600519",           // 终端 symbol（可选）→ 「去看历史数据」
  "source": "…",               // 出处
  "links": [ { "text": "…", "href": "#/…" } ]
}
```

## 五、纪律（不变）

- 每个数字都要能在站内 `data/history` 对账，或标明是公开历史事实
- 不荐股、不荐仓、不预测点位
- 不用「据说 / 业内普遍认为 / 必将 / 稳赚」
- 机构与人物只讲**公开的策略与历史**，不评价人、不影射
- 加密资产只讲机制与风险，不做价格判断
- 词条必须四段齐全（`one` / `metaphor` / `number` / `pit`），缺一段测试就红
- 分类与链接错位不会报错，只会让页面悄悄扑空——所以有审计脚本兜着

## 六、怎么加词条

不要直接手改 `content/_meta/glossary.json`（长 JSON 手改容易丢引号）。走两步：

```bash
# 1）在 drafts/ 写纯文本稿（格式见 _scripts/merge-terms.mjs 头部注释）
#    补老词条的一个字段时加一行 patch: yes，只改写了的字段，其余保留
# 2）合并进术语库（幂等：同 id 会覆盖）
node _scripts/merge-terms.mjs drafts/batch6.txt

# 3）构建产物 + 跑测试 + 跑审计
node _scripts/build-content.mjs
node _test/run-all.mjs && node _test/render-test.mjs
node _scripts/audit.mjs
```

`drafts/` 是**写作稿**，`content/_meta/glossary.json` 是**权威版本**——两者不一致时以 JSON 为准。

## 七、和行情终端的联动

终端（OpenFinLens）把每个标的映射到本站的术语页。三档出口，链接必须诚实到
"点进去就知道会看到什么"：精确页 / 概念页 / 搜索页。

两类**静默**的错位，各有一套自动校验：

| 错位 | 后果 | 谁来查 |
|---|---|---|
| 映射里的术语 id 拼错 / 本站删了词 | 点进去是「这个词还没有收录」 | 终端 `collect-academy-terms.mjs` 拉本站术语清单后当场自检，不对就退出 1 |
| 终端给了本站没有数据卡的标的页 | 点进去是半空页（承诺了「看这一页」，实际没数据） | 本站导出 `asset-ids.json`（哪些终端标的真有页），终端据此决定给不给标的页 |

两条链都是自动的：

- 本站 `build-content.mjs` → `data/content/asset-ids.json`（114 个终端标的在本站有页）
- 终端 `collect-academy-terms.mjs` → `data/academy-terms.json` + `js/data/academy-assets.js`，
  采集流水线 6h 档自动刷新。CI 的 paths-ignore 排除了 `data/**`，
  所以「清单过期」只能靠采集时自检抓，不能指望跑 CI 时抓。

本站还有 `_scripts/audit.mjs`：查词条的 sym / links / cat 错位，
CI 里跑，输出分类分布供人工审一眼归类合不合理。
