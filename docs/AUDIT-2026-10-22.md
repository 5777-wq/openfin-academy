## A-1　峰谷算法错，95/116 条序列输出荒谬值 `[已实测]`

**现象**（真浏览器抓取，非推算）

| 标的 | 页面显示 | 真实值 |
|---|---|---|
| 标普500 | 峰值 2026-10-21 / **谷底 1987-11-30** / 峰谷跌幅 **-97.0%** | -52.6%（2007-10→2009-02） |
| 贵州茅台 | 谷底 2003-09-30 / **-99.8%** | -59.9% |
| COMEX黄金 | 谷底 1999-08-31 / **-95.1%** | -42.1% |
| 腾讯 | **-99.9%** | -69.8% |

**根因**：`js/engine/instrument.js:22-26` 分别取全样本 max 和 min，不校验谁先谁后：

```js
let peak = first, trough = first;
for (const p of pts) {
  if (p.v > peak.v) peak = p;
  if (p.v < trough.v) trough = p;   // ← 这个 trough 可能出现在 peak 之前
}
```

`js/engine/instrument.js:54` 直接相除：`dropPct: (trough.v / peak.v - 1) * 100`。

统计确认：**116 条序列里 95 条 trough.t < peak.t**。

**怎么改**

`js/engine/instrument.js`：

```js
// 峰值取全样本最高；谷底只在该峰值之后找——「峰谷跌幅」讲的是「从高点跌下来」，
// 拿一个发生在前面的低点去除，得到的是两个不相干时刻的比值，不是回撤。
let peak = first, trough = null;
let peakIdx = 0;
for (let i = 0; i < pts.length; i++) {
  if (pts[i].v > peak.v) { peak = pts[i]; peakIdx = i; }
}
trough = pts[peakIdx];
for (let i = peakIdx; i < pts.length; i++) {
  if (pts[i].v < trough.v) trough = pts[i];
}
```

同时注意两个衍生口径：

- 如果序列是**收益率类**（`unit === '%'`），"峰谷"更该叫"区间变动"，`spreadPp = peak.v - trough.v` 要改用同一对点。现在用的是全局 min/max，同样错。
- `js/views/assets.js:159-160` 的标签写的是"峰值/谷底"，语义是"历史最高/历史最低"——这和"回撤的峰谷"不是一回事。**建议拆成两组数**：
  - 「历史最高 / 历史最低」→ 全样本 max/min（保留现语义，但标签改清楚）
  - 「最大回撤」→ 必须是 peak 在前、trough 在后（这才是读者说的"跌了多少"）

**验证**

1. 修完打开 `#/assets/usINX`，应显示最大回撤 -52.6%，峰值 2007-10-31、谷底 2009-02-27 之类（用当日真实数据核对）。
2. 加测试（`_test/run-all.mjs` 的 instrument 段，现在在 141 行附近）：

```js
// 夹具必须让「最高点出现在中间」——原来的夹具 100→120→60 最高点在开头，
// 这个 bug 永远测不出来。
const midPeak = {
  unit: '点', kind: '月收盘价',
  points: [
    { t: '2020-01-31', v: 80 },
    { t: '2020-02-29', v: 120 },   // 峰值在中间
    { t: '2020-03-31', v: 60 },    // 谷底在峰值之后
    { t: '2020-04-30', v: 40 },    // 后面的低点不属于「峰值前」
  ],
};
const mp = I.stats(midPeak);
eq('峰谷跌幅：谷底必须在峰值之后', Math.round(mp.dropPct), -67);  // 120 → 40
ok('谷底时间晚于峰值时间', mp.trough.t > mp.peak.t, mp.peak.t + ' / ' + mp.trough.t);

// 反向夹具：低点在前、高点在后，不能被算成回撤
const lowFirst = {
  unit: '点', kind: '月收盘价',
  points: [
    { t: '2020-01-31', v: 40 },
    { t: '2020-02-29', v: 120 },
  ],
};
const lf = I.stats(lowFirst);
ok('低点在前时不能报出巨大的负回撤', lf.dropPct === 0, String(lf.dropPct));
```

## A-2　异步视图串页：URL 是 1998，图是 1987 `[已实测]`

**现象**（注入延迟后实测）


产业链页同样：`h1 = 半导体`、热力图 `= AI 算力`。

**根因**：`js/app.js:313-322` 用"每次路由换一个新容器"来修竞态，但视图内部仍用**全局** `document.getElementById()` 取节点：

- `js/views/chain.js:59`（`chain-heat`）
- `js/components/replay-player.js` 里 19 处 `getElementById`（`rp-range`、`rp-date`、`val-*`……）

旧页面的 `await` 回来后，`document.getElementById('crisis-replay')` 命中的是**新页面**的同名节点，于是旧数据写进了新页面。

**怎么改（三步，缺一不可）**

1. **给容器一个 id，视图在容器内查询**。`js/app.js:319-322`：

```js
const host = document.createElement('div');
host.className = 'route-host';
host.id = 'route-host-' + (++routeSeq);   // 唯一，但不靠它取节点，靠作用域

view.appendChild(host);
```

2. **视图内部改成从 `view`/`host` 查**，不要用 `document`。`js/views/crisis.js`：

```js
function mountReplay(view, pkg) {
  const box = view.querySelector('[data-replay]');   // 不给固定 id，避免跨页重名
  ...
}
```

对应模板里把 `<div id="crisis-replay">` 改成 `<div data-replay>`。
`js/views/chain.js` 同理：`view.querySelector('[data-heat]')`。
`js/components/replay-player.js` 里 19 处 `document.getElementById(x)` 全部改成 `host.querySelector('#' + x)`——`render()` 已经把 `host` 存下来了（第 100 行 `host = container`），直接用。

3. **await 之后检查自己还在不在文档里**。`js/views/crisis.js:82` 之后：

```js
const pkg = await window.History.crisis(id);
if (!view.isConnected) return;   // 已经切走，别画了
const art = window.Content.article(id);
```

`js/views/chain.js:58` 之后同理。`js/views/article.js:29-36` 已经有一套 `__artSeq` 的写法，可以照抄思路。

4. **`app.js` 再加一道保险**：`js/app.js:380-389` 的 pending 处理里，成功分支也检查连接状态：

```js
pending
  .then(() => { if (host.isConnected) applyPageMeta(r, params, query, host, true); })
  .catch((e) => { ... });
```

**验证**

跑一遍现有的 `node _test/render-test.mjs`，应该全绿（说明没改坏）。
然后**加一条回归测试**——用真实浏览器或注入延迟都可以：

这条测试用 DOM 桩跑不了（要有真实的异步时序），建议单独建 `_test/race-test.mjs`，用当前的无浏览器 DOM 桩 + 手动控制 Promise 时序来实现。**最省事的做法**：在 view 上保留 `__artSeq` 之外再加一个 `__routeToken`，测试里直接断言"过期 token 的渲染不落盘"。

# E 批：根治机制（做完 C 再做）

## E-1　把「会动的数字」从 Markdown 里赶出去

**规则**：`content/**/*.md` 里不许手写下面这些——它们每天都会变：

- 近一年 / 近一月涨跌幅
- 最新价、「今天 xxx」
- 峰值 / 谷底 / 最大回撤（除非明确写了「截至 YYYY-MM-DD 的月线」，且加了断言）

**替代方案**（按优先级）：

1. **引用数据卡**：页面上已有由序列算出来的数据卡（`js/views/assets.js:147-170`），正文说「见上方数据卡」即可。
2. **占位符**：`{{series:GC00Y|mdd}}` → 构建时替换成数字，CI 校验。需要：
   - `_scripts/build-content.mjs` 加替换器
   - 替换失败（拿不到数据）就**构建失败**，不许留空
3. 如果非要手写，**必须**在 frontmatter 里写 `dataAsOf`，且 CI 断言「文章引用的序列最新日期 ≤ dataAsOf」。

## E-2　`dataAsOf` 自动派生

- **现状**：手写，永远停在写作那天。
- **改法**：`build-content.mjs` 里改成 `dataAsOf = min(文章引用的所有序列的最新日期)`；没引用序列的文章退回手写值。
- **最简可靠的做法**：先在 `index.json` 里**额外**输出一个 `dataAsOfActual`，页面同时显示「本文写于 X / 数据截至 Y」，让读者自己判断新鲜度。

## E-3　文档数字自动同步

`README.md` 的 189 / 90+ / 163 这类数字，改成构建时生成标记块：

```markdown
<!-- AUTO:stats -->
| 术语 | 213 |
| 标的 | 114 |
| 产业链 | 10 条 / 49 环节 / 177 只 |
<!-- /AUTO:stats -->
```

CI 里跑生成脚本，`git diff` 不为空就报错。**这是唯一能让文档不再漂的办法**——靠人记一定会再错。

## E-4　[功能建议] 历史分位条

`js/engine/percentile.js` 已经写好了 `percentile(values, v)` 和 `band(p)`（返回「历史极高位 / 偏高 / 中枢 / 偏低 / 极低位」），**但全站没有调用**。

接到标的页数据卡后面，加一条：

```
当前读数处于历史 87% 分位 · 历史偏高
[|||||||||||······]
```

- **用户价值**：这是小白最需要的一句判断，而且**完全符合本站「不预测、只呈现」的定位**（陈述事实，不是预测）。
- **成本**：**S**（引擎已有，只需约 30 行视图代码 + 一条测试）。
- 这是本次审查里**性价比最高的功能建议**。

# 附三：本文档数字的时效声明

本文档所有数字是 **2026-10-22** 的快照，基于 `data/history/*.json` 当日的值。
